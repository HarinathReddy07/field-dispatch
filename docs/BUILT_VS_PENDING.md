# Built vs pending

A requirement-by-requirement comparison of what the client asked for and what exists today.
Updated 2026-10-08 · branch `feat/ui` · commit `90ef386` · 48 commits.

**How to read it.** _Built_ means it exists and something was run to prove it (a passing test, a live HTTP/Socket.io call, or a browser run).
_Partial_ means the code exists but one piece could not be proven on this machine (no Docker, no phone, no real MinIO) or one detail is missing.
_Pending_ means not done yet. Items the client agreed to mock are listed at the end and are **not** pending.

## 4. Acceptance scenarios

| Scenario                | Required result                                       | Result                                                                                                                                     |
| ----------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| A1 Happy path           | Request to settlement, no manual database edits       | Passes: request, nearby, confirm, OTP arrival, start, 2 images, approve, one settlement; events DRAFT → … → SETTLED, no database edits     |
| A2 Rework               | Rework, new evidence, approve; earlier proof retained | Passes: reason required, new images needed, both evidence cycles and all events retained                                                   |
| A3 OTP security         | Wrong, expired, reused codes blocked                  | Passes: identical error for wrong and expired; reuse blocked; brute force locks the request, even for the correct code                     |
| A4 Concurrency          | Two confirms for one technician: one winner           | Passes: 6 of 6 rounds one 200 and one 409                                                                                                  |
| A5 Authorisation        | No leakage across users or to wrong roles             | Passes: foreign job 404 with no data; technician and requester on admin routes 403; mass-assignment and injection attempts changed nothing |
| A6 Duplicate settlement | Retries leave exactly one settlement                  | Passes: 10 attempts, 1 row, 1 event                                                                                                        |
| A7 Restart resilience   | State recovers after an API restart                   | Passes for a killed API process (mid-job and mid-review). Restarting a Docker container was not run                                        |
